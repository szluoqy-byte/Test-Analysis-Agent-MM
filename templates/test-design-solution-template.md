# 测试设计方案模板

本模板是 `test-design-agent` 的主输出。它承接已评审测试分析方案，在普通 `测试场景 -> 测试点 -> 测试点明细` 下补充 `TDI-*` 测试设计项；如果非成功测试点明细已有失败类型明细，则在 `TP-*-*-*` 下补充 `TDI-*`。

它不是完整测试用例文档，不包含前置步骤、测试步骤、自动化脚本或执行数据清单。

## 生成规则

- 主输出路径固定为：`${PROJECT_ROOT}/outputs/runs/<run-id>/deliverables/test-design-solution.md`。
- 如保留过程设计报告，路径固定为 `${PROJECT_ROOT}/outputs/runs/<run-id>/reports/test-design-report.md`。
- 主交付件固定使用中文术语和缩写：测试场景 `SC-*`、测试点 `TP-*`、测试点明细 `TP-*-*`、测试设计项 `TDI-*`，不展开英文全名。
- 测试场景 ID 使用 `SC-001` 起连续编号。
- 测试点 ID 使用 `TP-001` 起连续编号。
- 测试点明细 ID 继承测试点 ID，例如 `TP-001-001`、`TP-001-002`。
- 保留测试分析方案中的 `E2E场景测试` 测试点，通常作为每个测试场景下的首个 `TP-*`。
- `E2E场景测试` 是独立同级测试点，只维护 1 个端到端主流程成功闭环测试点明细；其他规则、异常、接口、权限、状态、回滚或补偿分支必须保留在同级 `TP-*` 下。
- 如果测试分析方案中存在接口测试或集成覆盖场景，测试设计方案必须继承“先接口/端点/集成点，再契约维度，再测试设计项”的结构；不得把多个接口的 TDI 混在无法定位目标接口的泛化 `TP-*` 下。
- 如果测试分析方案中某个非成功测试点明细存在 `TP-*-*-*` 第四层，测试设计方案必须保留该第四层，并在失败类型明细下生成 `TDI-*`。
- 如果测试分析方案中的单一弱结果分支停留在 `TP-*-*`，例如未注册、未找到、返回空列表、count=0、无记录、回滚或补偿状态确认，测试设计方案直接在该 `TP-*-*` 下生成 `TDI-*`，不为了设计阶段机械新增第四层。
- 测试设计方案不得新增、删除、合并或改写分析层级；发现分析层缺口时记录输入质量问题，必要时回到测试分析阶段修正。
- 测试设计项 ID 使用 `TDI-001` 起全局连续编号。
- 主输出默认按 `测试场景 -> 测试点 -> 测试点明细 -> 测试设计项` 组织；非成功测试点明细按 `测试场景 -> 测试点 -> 测试点明细 -> 失败类型明细 -> 测试设计项` 组织。
- 普通测试点明细或失败类型明细层保留一条 `- 预期结果：<明确预期结果或待人工分析确认>`，继承测试分析方案的判定语义。
- 测试设计项固定使用列表节点：`- TDI-001 <条件/数据/状态/组合>`，不得在 TDI 下一层重复写 `预期结果`。
- `TDI-*` 应优先写具体数据值、数据槽位、接口返回、状态值或组合，例如 `amount=1000.00；category=PAY；customer_id=AGT_CUSTOMER_001`。
- 接口类 `TDI-*` 不得写完整裸 URL，例如 `GET https://api.example.com/customers/?telephone_exact=...`；必须拆成同一行字段片段，例如 `接口=GET /customers/；telephone_exact=%2B225070000001；响应状态=HTTP 500`。
- `TDI-*` 不得写结果或动作表达，例如“发送通知”“显示提示”“自动填充”“接口调用正确”“处理成功”“删除成功”；应改写为 `字段=值；状态=值；依赖=值；接口返回=值` 等组合。
- 重复模式必须补充差异维度，例如 `场景=Add Payment`、`渠道=APP`、`操作=Delete Favorite`、`接口=POST /payments/`、`数据依赖=预验证已失败`。
- 接口契约叶子节点应根据已明确字段约束展开代表性设计项，例如 `amount=1000.00；category=PAY；customer_id=AGT_CUSTOMER_001`、`amount=1000；缺少两位小数`、`amount=1000.001；超过两位小数`、`category=REFUND；枚举值非PAY`。
- 超时、回滚、补偿或外部依赖恢复类叶子节点应使用可观察条件，例如 `查询返回count=1；payment_status=SUCCESS`、`查询返回count=0；payment_status=FAILED`、`查询超时；payment_status=TIMEOUT`。
- 主输出不得使用测试设计项表格，避免 Markdown 转脑图时丢失层级。
- `TDI-*` 后的正文写代表性条件、数据、状态或组合，不写“验证功能正常”这类泛化标题。
- `预期结果` 只能写需求、设计方案或上游测试分析方案明确支持的结果；如果需求和设计方案没有明确错误提示、状态变化、错误码、返回内容或记录变化，写 `待人工分析确认`。
- 主输出不设置 `未明确规则` 章节，也不设置独立待确认信息清单。
- 主输出不得使用 Markdown 加粗语法，例如 `**文本**` 或 `__文本__`。
- 不要把内部测试技术路由、方法证据、专家评分、quality gate 结果或 memory 更新建议写入主输出。

## 生成规则

- 主输出路径固定为：`${PROJECT_ROOT}/outputs/runs/<run-id>/deliverables/testcase-title-outline.md`。
- 如保留过程分析报告，路径固定为 `${PROJECT_ROOT}/outputs/runs/<run-id>/reports/test-analysis-report.md`。
- 运行任务清单、上下文和澄清记录分别写入 `process/task-list.md`、`process/context-pack.md` 和 `process/clarification-session.md`。
- 标题项 ID 使用 `TCT-001` 起全局连续编号。
- 测试点 ID 在场景测试点中使用 `TP-001` 连续递增，接口测试点使用 `ITP-001` 连续递增。
- 主输出必须按 `测试场景 -> 测试点 -> 测试用例标题项` 组织。
- 接口对象可以独立按 `接口 -> 接口测试点 -> 测试用例标题项` 组织。
- `输入条件与数据依赖` 必须写明后续完整用例编写所需的角色、状态、字段、枚举、边界、依赖服务、配置或数据准备约束。
- `判定关注` 只写观察方向或 oracle，不写完整预期清单。
- 不要把内部方法路由、方法证据、专家评分或 memory 更新建议写入主输出。
- 没有待确认问题时，`## 5. 待确认信息` 写“本次无待确认信息。”，不要保留空问题行。

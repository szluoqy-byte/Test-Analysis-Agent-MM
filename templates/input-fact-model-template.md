# 输入事实模型模板

本模板用于承载 `input-fact-modeling` 的输出。输入事实模型是需求文档、可选设计方案和上下文补充的事实化结果，用于 `clarification-gate`、`testing-method-router` 和测试分析方案生成；它不包含测试技术路由、测试点或测试设计项。

```markdown
# 输入事实模型

## 1. 输入来源

| 来源类型 | 文件/来源 | 范围 | 说明 |
|---|---|---|---|
| 需求 |  |  |  |
| 设计方案 |  |  | 未提供/已提供 |
| Context Pack | process/context-pack.md |  |  |

## 2. 事实清单

| 事实ID | 来源 | 对象/范围 | 事实内容 | 约束/条件 | 可观察结果 | 缺口/冲突 |
|---|---|---|---|---|---|---|
| FACT-001 | 需求：<标题/段落/表格行> |  |  |  |  | 无 |
| FACT-002 | 设计：<标题/接口/状态说明> |  |  |  |  | 无 |

## 3. 需求-设计映射

| 需求事实ID | 设计事实ID | 关系 | 说明 |
|---|---|---|---|
| FACT-001 | FACT-002 | 补充/一致/冲突/无设计依据/设计新增 |  |

## 4. 待确认事项

| 编号 | 来源事实 | 问题 | 影响 | 处理建议 |
|---|---|---|---|---|
| CQ-001 | FACT-001 |  |  | 后续预期结果写待人工分析确认/交给 clarification-gate 收口 |

## 5. 来源与应用说明

| 来源文件 | 应用状态 | 应用位置 | 说明 |
|---|---|---|---|
| process/context-pack.md | applied/not_applicable/insufficient_evidence/conflict_with_requirement | 输入事实建模 |  |
```

## 使用规则

- `事实ID` 使用 `FACT-001` 起连续编号，不按需求/设计分两套编号。
- `来源` 必须能回到需求文档、设计方案、context pack 或 project knowledge 的标题、段落、表格行、接口字段或状态说明。
- `事实内容` 只写输入材料明确表达的事实，不写测试技术、测试点、测试步骤或推断业务规则。
- `约束/条件` 写事实成立条件、输入条件、状态条件、权限条件、字段约束、配置条件或依赖条件；没有则写 `无`。
- `可观察结果` 写可被验证的行为、状态、接口响应、数据变化、权限差异、日志/消息/外部依赖结果；依据不足时写 `待人工分析确认`。
- `缺口/冲突` 只记录影响测试分析、预期结果或覆盖判断的缺口；普通措辞问题不进入待确认事项。
- `需求-设计映射` 不要求每条事实都有设计事实；没有设计方案时统一记录 `无设计依据` 或在说明中写 `未提供设计方案`。

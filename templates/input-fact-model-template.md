# 输入事实模型模板

构建当前运行目录下的 `process/input-fact-model.json` 时使用 `templates/input-fact-model-json-template.json`；本文件只作为 `process/input-fact-model.md` 派生阅读版样式参考。输入事实模型用于 `testing-method-router` 和测试分析方案生成；它不包含测试技术路由、测试点或测试用例。

```markdown
# 输入事实模型

## 1. 输入来源

| 来源类型 | 文件/来源 | 位置/章节 | 说明 |
|---|---|---|---|
| 需求 |  |  |  |
| 设计方案 |  |  | 未提供/已提供 |
| Context Pack | process/context-pack.json |  |  |
| Rules Pack | process/rules-pack.json |  |  |

## 2. 事实清单

| 事实ID | 来源类型 | 文件/来源 | 位置/章节 | 对象/范围 | 事实内容 | 约束/条件 | 可观察结果 |
|---|---|---|---|---|---|---|---|
| FACT-001 | 需求 | <需求文档路径或标题> | <标题/段落/表格行> |  |  |  |  |

| 需求事实ID | 设计事实ID | 关系 | 说明 |
|---|---|---|---|

| 来源文件 | 应用状态 | 应用位置 | 说明 |
|---|---|---|---|
| process/context-pack.json | applied/not_applicable/insufficient_evidence/conflict_with_requirement | 输入事实建模 |  |
```

## 使用规则

- `事实ID` 使用 `FACT-001` 起连续编号，不按需求/设计分两套编号。
- 事实清单按输入来源抽取和展示，`来源类型`、`文件/来源`、`位置/章节` 必须能回到需求文档、设计方案、rules-pack 规则路径、context pack 动态来源路径或已读取动态来源的标题、段落、表格行、接口字段或状态说明。
- `事实内容` 只写输入材料明确表达的事实，不写测试技术、测试点、测试步骤或推断业务规则。
- `约束/条件` 写事实成立条件、输入条件、状态条件、权限条件、字段约束、配置条件或依赖条件；没有则写 `无`。
- `可观察结果` 写可被验证的行为、状态、接口响应、数据变化、权限差异、日志/消息/外部依赖结果；依据不足时只写输入明确支持的保守结果方向，不补写错误码、提示文案、状态值或阈值。
- `需求-设计映射` 不要求每条事实都有设计事实；没有设计方案时统一记录 `无设计依据` 或在说明中写 `未提供设计方案`。

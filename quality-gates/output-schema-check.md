# 质量门禁：输出结构检查

## 目的

确保主输出结构稳定、可被后续完整测试用例编写消费，并能支持后续工具化处理。

## 主输出必需章节

- `# <需求名称> 测试设计方案`
- `## 1. 需求范围`
- `## 2. 测试场景与测试设计`

主输出不得设置 `## 3. 未明确规则` 或独立待确认信息章节。

## 主输出必需结构

测试场景：

```markdown
### 场景 SC-001：<测试场景名称>
```

测试点：

```markdown
#### 测试点 TP-001：<测试点>
```

测试设计项：

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TDI-001 | <代表性条件、数据、状态或组合> | <明确预期结果或待人工分析确认> |

## 字段规则

- `场景 ID` 符合 `SC-001` 格式并按顺序递增。
- `测试点 ID` 符合 `TP-001` 格式并按顺序递增。
- `测试设计项 ID` 符合 `TDI-001` 格式并按顺序递增。
- 主交付件只使用中文术语和缩写 `SC`、`TP`、`TDI`；不得展开英文全名或使用 `TD-*`、`TC-*`、`TCT-*`、`TI-*`、`ITP-*`、`ITDI-*`。
- 除非 `预期结果` 精确写 `待人工分析确认`，否则必填字段不能为空。
- 主输出不得用“见原始需求”“见设计方案”“按需求实现”“同上”等占位替代后续完整用例编写必须知道的信息。
- 主输出不得包含 `前置步骤`、`测试步骤`、`操作步骤`、`执行数据` 或自动化脚本。
- 主输出不得包含旧版主交付件字段；字段禁用清单以 `bin/lint-test-design-solution.py` 为准。

## 预期结果规则

- 需求或设计方案明确结果时，写简短预期结果。
- 需求或设计方案未说明错误提示、状态变化、错误码、接口返回内容、消息发送结果或数据记录变化时，写 `待人工分析确认`。
- 不得编造错误码、错误提示、状态枚举、接口字段或数据库字段。

## 过程分析报告

如生成过程分析报告，建议包含以下章节，便于专家审查：

- `## 1. 分析范围`
- `## 2. 记忆上下文包摘要`
- `## 3. 需求结构化摘要`
- `## 4. 待确认治理摘要`
- `## 5. 测试分析维度与测试技术路由`
- `## 6. 方法分析证据摘要`
- `## 7. 测试点明细`
- `## 8. 覆盖审查结果`
- `## 9. 独立评审结果`
- `## 10. 质量门禁结果`
- `## 11. 专家评审评分`
- `## 12. 建议沉淀的记忆更新`

## 运行产物路径

- 每次运行必须先将当前 agent 会话工作目录固定为 `PROJECT_ROOT`，再创建独立目录 `${PROJECT_ROOT}/outputs/runs/<run-id>/`。
- 不得从需求文档路径向上查找或反推 `PROJECT_ROOT`。
- 运行目录下必须按类别写入固定文件名，不得使用模型自行生成的文件名。
- 测试设计方案路径必须是 `${PROJECT_ROOT}/outputs/runs/<run-id>/deliverables/test-design-solution.md`，这是唯一默认主交付件。
- 上下文包快照路径必须是 `${PROJECT_ROOT}/outputs/runs/<run-id>/process/context-pack.md`。
- 待确认治理记录路径必须是 `${PROJECT_ROOT}/outputs/runs/<run-id>/process/clarification-session.md`，仅在存在待确认候选并需要记录治理结果时生成。
- 过程分析报告路径建议是 `${PROJECT_ROOT}/outputs/runs/<run-id>/reports/test-analysis-report.md`。
- 默认不得生成 `<需求文件名安全短名>.test-points.md`、`<需求文件名安全短名>.testpoint-details.md` 或其他同义文件。
- 报告可额外展示相对路径 `outputs/runs/<run-id>/...`，但实际文件不得写入 skill 目录、插件缓存目录或 `.claude-plugin/` 目录。
- 不允许使用只含需求文件名的固定路径覆盖历史运行产物。

# 测试分析方案检查

用于检查 `deliverables/test-analysis-solution.md` 是否停留在测试分析方案粒度，并且能支撑 `test-design-agent` 继续细化。

## 必须满足

- 主输出按 `测试场景 -> 测试点 -> 测试点明细` 组织；非成功测试点明细按 `测试场景 -> 测试点 -> 测试点明细 -> 失败类型明细` 组织。
- 主输出包含 `## 1. 需求范围` 和 `## 2. 测试场景与测试点`。
- 每个测试场景下包含 `E2E场景测试` 测试点。
- 每个测试点至少包含 1 个测试点明细。
- 场景 ID 使用 `SC-001` 起连续编号。
- 测试点 ID 使用 `TP-001` 起连续编号。
- 测试点明细 ID 使用所属测试点前缀，例如 `TP-001-001`。
- 非成功测试点明细下的失败类型明细 ID 使用所属测试点明细前缀，例如 `TP-001-002-001`。
- 主交付件只使用中文术语和缩写 `SC`、`TP`、`TP-*-*`、`TP-*-*-*`；不得展开英文全名或使用其他编号体系。
- 每个普通测试点明细包含 `测试点详情` 和 `预期结果`；非成功测试点明细由第四层失败类型明细包含 `测试点详情` 和 `预期结果`。
- 测试点明细表达分析层规则分支、路径分支、状态分支、权限分支、接口契约分支或风险分支。
- 只有非成功测试点明细新增第四层；是否新增第四层由 `TP-*-*` 明细决定，不由 `TP-*` 测试点主题决定。
- 预期结果为空时不允许通过。
- 当需求和设计方案没有明确错误提示、状态变化、错误码、返回内容或记录变化时，预期结果必须写 `待人工分析确认`。
- 主输出不设置 `未明确规则` 章节。
- 主输出不设置独立待确认信息清单。

## 禁止出现

- `TDI-*`、`测试设计项` 或测试设计项表格。
- 旧版主交付件字段；字段禁用清单以 `bin/lint-test-analysis-solution.py` 为准。
- 完整测试用例字段：`前置步骤`、`测试步骤`、`操作步骤`、`执行数据`、`自动化脚本`。
- 编造的错误码、错误提示、状态枚举、接口字段或数据库字段。
- `见需求`、`见设计方案`、`按需求`、`同上`、`TBD` 等非自包含占位。

## 常见失败

- 把测试点明细写成“验证功能正常”“异常场景覆盖”。
- 缺少场景级 `E2E场景测试` 测试点。
- 非成功测试点明细没有继续拆分失败类型明细。
- 把第四层直接挂在 `TP-*` 测试点下，或把 `TP-*` 写成非成功路径主题。
- 把多个互相独立的状态、权限或接口契约塞进一条测试点明细。
- 提前输出具体代表性数据、边界值或组合，让测试分析方案变成测试设计方案。
- 需求没有说明错误码，却写出具体错误码。
- 需求没有说明状态变化，却写出具体终态。
- 为缺口单独新增 `## 3. 未明确规则` 或待确认章节，而不是在对应测试点明细的预期结果写 `待人工分析确认`。

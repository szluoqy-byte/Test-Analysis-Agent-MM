# 质量门禁：测试技术应用检查

## 目的

确保 Agent 真正应用了相关测试分析维度和测试技术，而不是生成泛化测试点。

## 必需输入

- 测试分析维度与测试技术路由表。
- 方法分析证据摘要。
- 测试分析方案。
- 如有过程报告，读取其中的测试分析方案映射。
- 输入事实模型。

## 失败条件

- 过程报告没有测试技术路由表。
- 路由表缺少分析维度，无法判断为什么选择某个测试技术。
- 过程报告没有方法分析证据摘要。
- 标记为 `必选` 的测试技术没有映射到场景测试点/接口契约分析候选且没有待确认问题。
- 标记为 `必选` 的测试技术没有方法证据且没有待确认问题解释。
- 过程报告的测试分析方案映射缺少方法证据关联。
- 需求信号明显需要某测试技术，但被跳过且没有解释。
- 过程报告中的方法证据与测试分析方案中的测试点或测试点明细明显冲突。

## 警告条件

- 大多数行只使用泛化功能分析。
- 高风险测试技术被标记为可选但没有理由。

## 通过条件

- 每个选中测试技术都出现在路由表中。
- 每个选中测试技术都体现在方法证据、测试点、测试点明细或待确认问题中。
- 每个适用分析维度都体现在场景、场景条件、测试点、测试点明细或待确认问题中。

# 深度评审 Rubric

深度评审只在用户明确要求或高风险场景下执行。

## 分析方案

- 场景树是否表达真实业务路径，且不超过 3 层。
- 叶子场景是否都有 E2E 测试点。
- 测试点是否能追踪到需求、设计、规则、方法证据或风险。
- 测试点是否保持分析粒度，没有提前写用例、步骤、数据或预期。

## 设计方案

- 每个测试点是否至少有一个测试用例。
- 测试用例是否具体到可执行实例。
- 测试数据是否明确且可追踪。
- 步骤是否按顺序表达动作和步骤预期。
- 最终预期是否有依据，依据不足时是否保守表达。

## 高风险信号

- 资损、越权、重复扣减、不可逆状态变化没有独立测试点。
- 测试用例只写抽象条件，没有可执行步骤。
- 接口类用例无法定位接口、参数、响应或副作用。

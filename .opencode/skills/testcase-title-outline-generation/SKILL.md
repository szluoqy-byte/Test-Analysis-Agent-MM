# 测试用例标题大纲生成

本 skill 负责从 `testpoint-generation` 产出的测试场景、场景测试条件、场景测试点和接口测试点生成 `测试用例标题大纲`。它使用本仓库内置的 `knowledge/test-techniques/` 测试技术库，在标题级测试设计阶段回答“如何把测试点展开成标题项”，但输出停留在测试用例标题粒度，不进入完整测试用例编写。

## 路径解析规则

- 本 skill 中所有 `knowledge/...`、`templates/...`、`quality-gates/...` 路径均为仓库根目录相对路径。
- 读取测试技术时，先读取 `knowledge/test-techniques/README.md`，再按 README 路由读取同目录下的具体技术文件。
- 粒度边界读取 `knowledge/test-analysis-methodology.md` 和 `knowledge/testcase-title-outline-standard.md`。
- 输出结构读取 `templates/testcase-title-outline-template.md`。

## 职责边界

- 输出“应该有哪些测试用例标题项”，不输出完整用例正文。
- 选择主测试技术和辅助测试技术，并说明覆盖意图。
- 为每个标题项补充 `输入条件与数据依赖` 和 `判定关注`。
- 保留测试点到标题项的层级关系。
- 不生成前置步骤、测试步骤、完整预期结果或自动化脚本。

## 输入

- 测试场景清单、场景测试条件、场景测试点和接口测试点。
- 结构化需求模型。
- 设计方案事实摘要，尤其是接口、字段、状态、权限、数据依赖、配置开关、异常处理和非功能指标。
- `context-pack.md` 中与本次相关的项目事实、历史缺陷和输出偏好。
- `ME-*` 方法分析证据摘要。
- 已收口的待确认候选。

## 生成步骤

1. 按 `knowledge/test-analysis-methodology.md` 检查输入是否满足 `测试场景 -> 测试点` 的层级关系；如果测试点已写成完整用例，先上收为验证目标。
2. 按 `knowledge/testcase-title-outline-standard.md` 确认标题项粒度：标题项应是“用例名称 + 设计条件摘要”，不得包含可执行步骤或完整预期。
3. 对每条测试点识别主要信号：流程、边界、枚举、字段格式、字段长度、组合、判定、周期、状态、权限、接口、历史缺陷、风险或质量属性。
4. 按 `knowledge/test-techniques/README.md` 选择一个主测试技术，必要时选择一个辅助测试技术。
5. 基于场景测试条件、需求事实和设计方案事实，生成 1-N 个测试用例标题项：
   - 主路径或核心成功条件至少 1 个标题项。
   - 明确边界、枚举、状态、权限、接口错误码、组合或异常处理时，按风险拆出独立标题项。
   - 同一验证目标只是输入值不同且定位方向相同的，可合并为一个标题项，并在 `输入条件与数据依赖` 中列出取值范围。
6. 标题命名使用“验证 + 被测对象 + 在<条件/场景>下 + <验证目标>”结构；标题必须能独立表达验证对象、条件和目标。
7. `输入条件与数据依赖` 应从需求、设计方案和场景测试条件中提取，不得编造：
   - 角色、权限、账号类型。
   - 业务对象状态、字段取值范围、枚举、长度、格式、金额、数量、时间窗口。
   - 依赖服务、配置开关、外部系统、消息、接口字段、鉴权方式、幂等键。
   - 数据准备约束或数据间依赖，例如主子表、订单与支付记录、缓存与数据库一致性。
8. `判定关注` 只写观察方向，不写完整预期清单；可包括页面展示、接口响应、状态变化、错误码、数据记录、通知、日志、权限拦截、幂等结果或性能指标。
9. `级别` 使用 `Level 0` 到 `Level 4`；优先继承测试点级别，并结合风险、业务影响、核心流程和项目 memory 调整。
10. 对缺少的入口、角色、字段、阈值、状态集合、接口契约、错误码、配置开关、依赖系统或判定依据，写入 `待确认信息`，不在标题项中编造。
11. 去重：如果两个标题项的被测对象、条件、验证目标和判定关注相同，只保留一个；如果只是标题措辞不同，不得重复输出。
12. 按 `templates/testcase-title-outline-template.md` 写入主交付件，保持 `测试场景 -> 测试点 -> 测试用例标题项` 层级。

## 输出格式

每个测试点下使用以下表格：

| 标题项 ID | 测试用例标题 | 覆盖意图 | 级别 | 输入条件与数据依赖 | 判定关注 | 待确认信息 |
|---|---|---|---|---|---|---|
| TCT-001 | 验证<被测对象>在<条件/场景>下<验证目标> | 主路径/边界/异常/状态/接口契约/权限/数据一致性 | Level 1 | <角色、状态、字段、枚举、边界、依赖服务或配置> | <响应、状态、记录、错误码、日志、页面或通知> | 无 |

接口测试点标题项仍使用 `TCT-*` 全局连续编号，不另起 `ITCT-*`，以避免后续标题项评审、细化或落地时出现重复编号体系。

## 约束

- 不输出 `前置步骤`、`测试步骤`、`预期结果`、`操作步骤`、`执行数据`、`自动化脚本` 等字段。
- 不把“正向/异常”作为唯一覆盖意图；必须说明对应主路径、边界、权限、状态、接口契约、数据一致性等真实意图。
- 不为了凑数量生成重复标题项。
- 不强制每个测试点只生成一条标题项；高风险、边界、状态、权限、接口和组合测试点可以生成多条。
- 不强制每个具体输入值都生成独立标题项；仅当输入值代表不同边界、分支、错误类型或风险定位方向时才拆分。
- 如果覆盖补全依赖的枚举值、容量阈值、兼容范围、目标语言、性能指标、错误码或异常处理规则缺失，应登记待确认信息，不编造具体取值。

# 示例需求：限时优惠与订单支付 测试点分析报告

## 1. 分析范围

- 输入文档：examples/requirements/complex-promotion-requirement.md
- 运行目录：examples/outputs/runs/complex-promotion-requirement-run
- 测试用例标题大纲：examples/outputs/runs/complex-promotion-requirement-run/deliverables/testcase-title-outline.md
- 完整报告：examples/outputs/runs/complex-promotion-requirement-run/reports/test-analysis-report.md
- 分析范围：优惠券领取、使用、试算、支付、状态、库存、权限、接口、兼容性
- 非范围：不生成测试用例、测试步骤、自动化脚本

## 2. 记忆上下文包摘要

- 使用风险优先、边界优先、状态优先、权限优先、接口契约优先、数据一致性优先分析。
- 重点关注重复提交、异步回调、库存扣减、优惠券状态和版本兼容。

## 3. 需求结构化摘要

- 角色：普通用户、运营管理员、客服。
- 核心对象：优惠券活动、优惠券、订单、库存、支付回调、操作日志。
- 关键规则：活动时间、库存、单用户领取限制、适用商品、最低门槛、会员叠加折扣、过期不可用。
- 状态：待支付、已支付、订单关闭、优惠券未使用、锁定、已使用、释放。
- 接口：试算接口、支付接口、支付系统异步回调。
- 兼容：App 5.0 及以上展示新规则，老版本展示受限。

|---|---|---|---|---|---|---|---|

| TP-007 | 优惠计算 | 过期优惠券不应可用于试算和支付 | 状态迁移 | 状态迁移 | 优惠券过期后不能使用 | Level 0 | 防止过期权益被使用 |

| TP-010 | 权限 | 普通用户只能使用自己领取且未过期的优惠券 | 权限角色 | 权限矩阵 | 普通用户只能使用自己领取且未过期的优惠券 | Level 0 | 防止横向越权 |

| ITP-003 | 接口 | 支付接口应校验订单号、优惠券 ID 和支付渠道等关键入参 | 接口契约 | 接口契约 | 支付接口提交订单号、优惠券 ID 和支付渠道 | Level 1 | 字段契约影响支付提交 |

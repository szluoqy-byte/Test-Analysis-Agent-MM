## 1. 需求范围

| 字段 | 内容 |
|---|---|
| 需求 ID | 示例需求 |
| 需求名称 | 限时优惠与订单支付 |
| 需求来源 | examples/requirements/complex-promotion-requirement.md |
| 设计方案来源 | 未提供 |
| 需求摘要 | 大促期间支持限时优惠券领取、使用、支付锁定、库存扣减、支付回调和版本兼容。 |
| 设计方案摘要 | 未提供接口路径、金额精度、错误码、不可用原因枚举、幂等键和回调乱序规则。 |

## 2. 测试场景与测试设计

### 场景 SC-001：限时优惠券领取

| 字段 | 内容 |
|---|---|
| 场景目标 | 验证用户在活动时间、库存和重复领取限制下的领券规则。 |
| 场景入口/触发方式 | 用户领取限时优惠券。 |
| 执行用户/角色 | 普通用户。 |
| 业务与设计约束 | 活动有开始和结束时间；库存为 0 不能领取；每个用户同一活动最多领取 1 张。 |

#### 测试点 TP-001：验证活动时间窗口内允许领取

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-001 | 活动开始时间与结束时间之间，优惠券库存大于 0，用户未领取过 | 领取成功。 |
| TD-002 | 活动开始前或结束后，优惠券库存大于 0，用户未领取过 | 待人工分析确认 |

#### 测试点 TP-002：验证库存为 0 时不能领取

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-003 | 活动期内优惠券库存为 0 | 领取失败。 |

#### 测试点 TP-003：验证同一用户同一活动最多领取 1 张

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-004 | 同一用户重复领取同一活动优惠券 | 只保留 1 张优惠券权益。 |

### 场景 SC-002：优惠券可用性与优惠计算

| 字段 | 内容 |
|---|---|
| 场景目标 | 验证商品范围、订单金额、会员等级和过期状态对优惠券使用的影响。 |
| 场景入口/触发方式 | 用户在下单或试算时选择优惠券。 |
| 执行用户/角色 | 普通用户、VIP 用户。 |
| 业务与设计约束 | 优惠券仅适用于活动配置商品分类；订单金额必须大于等于最低门槛；VIP 可以叠加会员折扣；优惠券过期后不能使用。 |

#### 测试点 TP-004：验证商品分类不适用时优惠券不可用

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-005 | 订单商品分类不在活动适用范围内 | 优惠券不可用。 |

#### 测试点 TP-005：验证订单金额门槛边界

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-006 | 订单金额等于优惠券最低使用门槛 | 优惠券可用。 |
| TD-007 | 订单金额低于优惠券最低使用门槛 | 优惠券不可用。 |

#### 测试点 TP-006：验证会员折扣叠加规则

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-008 | VIP 用户满足商品范围和金额门槛并使用优惠券 | 可叠加会员折扣。 |
| TD-009 | 普通用户满足商品范围和金额门槛并使用优惠券 | 不可叠加会员折扣。 |
| TD-010 | VIP 会员折扣与优惠券的计算顺序 | 待人工分析确认 |

### 场景 SC-003：优惠券支付

| 字段 | 内容 |
|---|---|
| 场景目标 | 验证订单支付状态、优惠券归属和支付请求重复提交下的处理。 |
| 场景入口/触发方式 | 前端调用支付接口提交订单号、优惠券 ID 和支付渠道。 |
| 执行用户/角色 | 普通用户。 |
| 业务与设计约束 | 待支付订单可以使用优惠券支付；已支付订单不能再次使用优惠券；重复支付不能重复扣减优惠券和库存。 |

#### 测试点 TP-007：验证待支付订单可使用本人有效优惠券支付

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-011 | 待支付订单使用本人领取且未过期优惠券支付 | 支付成功后更新订单状态、优惠券状态、库存数量并记录操作日志。 |

#### 测试点 TP-008：验证已支付订单不能再次使用优惠券

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-012 | 已支付订单再次使用优惠券支付 | 支付失败。 |
| TD-013 | 已支付订单再次支付时的错误码或提示 | 待人工分析确认 |

#### 测试点 TP-009：验证重复支付不会重复扣减

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-014 | 同一订单重复提交支付请求 | 不重复扣减优惠券和库存。 |
| TD-015 | 支付幂等键或重复请求识别规则 | 待人工分析确认 |

### 场景 SC-004：支付超时、失败与回调

| 字段 | 内容 |
|---|---|
| 场景目标 | 验证支付超时、支付失败和支付成功回调后的状态与数据一致性。 |
| 场景入口/触发方式 | 支付系统异步回调或订单超时关闭任务。 |
| 执行用户/角色 | 支付系统、系统任务。 |
| 业务与设计约束 | 支付超时后订单关闭并释放已锁定优惠券；支付失败或回调超时时保持订单待支付并允许重新支付；支付成功后更新订单、优惠券、库存和日志。 |

#### 测试点 TP-010：验证支付超时关闭订单后释放优惠券

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-016 | 订单支付超时且优惠券已锁定 | 订单关闭，已锁定优惠券释放。 |

#### 测试点 TP-011：验证支付失败或回调超时保持可重新支付

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-017 | 支付失败或支付回调超时 | 订单保持待支付，允许用户重新支付。 |

#### 测试点 TP-012：验证支付成功回调后的数据一致性

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-018 | 支付成功回调到达后更新订单、优惠券、库存和操作日志 | 订单状态、优惠券状态、库存数量和操作日志更新。 |
| TD-019 | 支付成功回调重复到达或乱序到达 | 待人工分析确认 |

### 场景 SC-005：接口与版本兼容

| 字段 | 内容 |
|---|---|
| 场景目标 | 验证试算接口、支付接口和 App 版本差异。 |
| 场景入口/触发方式 | 前端调用试算接口和支付接口；App 展示优惠信息。 |
| 执行用户/角色 | 普通用户、VIP 用户、老版本 App 用户。 |
| 业务与设计约束 | 试算接口返回优惠金额、应付金额和不可用原因；支付接口提交订单号、优惠券 ID 和支付渠道；新规则只对 App 5.0 及以上版本生效。 |

#### 测试点 TP-013：验证优惠试算接口返回金额与不可用原因

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-020 | 优惠券可用时调用试算接口 | 返回优惠金额和应付金额。 |
| TD-021 | 优惠券不可用时调用试算接口 | 返回不可用原因。 |
| TD-022 | 试算接口金额精度、不可用原因枚举或错误码 | 待人工分析确认 |

#### 测试点 TP-014：验证 App 版本兼容展示

| 测试设计项 ID | 测试设计项 | 预期结果 |
|---|---|---|
| TD-023 | App 5.0 及以上版本使用新优惠券规则 | 新优惠券规则生效。 |
| TD-024 | 老版本 App 展示优惠券不可用原因 | 不展示叠加折扣明细。 |

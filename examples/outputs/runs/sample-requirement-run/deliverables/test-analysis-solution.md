# 示例需求：订单取消 测试分析方案

## 1. 需求范围

| 字段 | 内容 |
|---|---|
| 需求 ID | 示例需求 |
| 需求名称 | 订单取消 |
| 需求来源 | examples/requirements/sample-requirement.md |
| 设计方案来源 | 未提供 |
| 需求摘要 | 用户在订单未完成前可以取消订单；取消后订单不可继续支付，系统释放库存并记录取消原因。 |
| 设计方案摘要 | 未提供接口路径、请求方式、鉴权方式、错误码、失败原因枚举和幂等实现。 |
| 本次覆盖范围 | 普通用户取消本人订单、非本人订单权限、订单状态限制、重复取消、客服协助取消、库存释放、操作日志、取消接口结果。 |
| 本次不覆盖内容 | 退款、售后、物流拦截、客服审核后台详细流程。 |

## 2. 测试场景与测试点

### SC-001 普通用户取消订单

| 字段 | 内容 |
|---|---|
| 场景目标 | 验证普通用户在不同归属和订单状态下的取消规则。 |
| 场景入口/触发方式 | 前端调用订单取消接口。 |
| 执行用户/角色 | 普通用户。 |
| 业务与设计约束 | 普通用户只能取消自己的订单；待支付订单允许取消；已发货订单不允许取消；取消成功后订单不可继续支付。 |

#### TP-001 E2E场景测试

##### TP-001-001 普通用户取消本人待支付订单主流程成功闭环

- 测试点详情：验证普通用户取消本人名下待支付订单时，取消请求、订单状态、支付限制、库存释放和取消原因记录能够形成完整业务闭环。

- 预期结果：取消成功，订单不可继续支付，库存释放并记录取消原因。

#### TP-002 验证待支付本人订单允许取消

##### TP-002-001 待支付本人订单取消请求被允许

- 测试点详情：验证普通用户取消本人名下待支付订单时，系统允许取消并完成相关业务处理。

- 预期结果：取消成功，订单不可继续支付，库存释放并记录取消原因。

#### TP-003 验证订单取消权限控制

##### TP-003-001 非本人订单取消请求被拒绝

###### TP-003-001-001 非本人订单归属校验失败

- 测试点详情：验证普通用户尝试取消非本人订单时，系统能够识别订单归属不匹配并阻止取消。

- 预期结果：取消失败。

###### TP-003-001-002 权限校验失败结果表达

- 测试点详情：验证非本人订单取消失败时，错误码、错误提示或失败原因是否有明确契约支撑。

- 预期结果：请求被拒绝，系统不产生成功态数据变更；不补写未说明的错误码、提示文案或状态值。

#### TP-004 验证订单状态取消限制

##### TP-004-001 已发货本人订单取消不允许

###### TP-004-001-001 已发货状态不允许取消

- 测试点详情：验证普通用户取消本人名下已发货订单时，系统能够按订单状态限制拒绝取消。

- 预期结果：取消失败。

###### TP-004-001-002 状态限制失败结果表达

- 测试点详情：验证已发货订单取消失败时，错误码、错误提示或状态保持规则是否有明确契约支撑。

- 预期结果：请求被拒绝，系统不产生成功态数据变更；不补写未说明的错误码、提示文案或状态值。

### SC-002 重复取消与副作用控制

| 字段 | 内容 |
|---|---|
| 场景目标 | 验证重复取消不会造成重复释放库存或重复副作用。 |
| 场景入口/触发方式 | 同一订单重复提交取消请求。 |
| 执行用户/角色 | 普通用户。 |
| 业务与设计约束 | 用户重复提交取消请求时，系统不能重复释放库存。 |

#### TP-005 E2E场景测试

##### TP-005-001 重复取消场景主流程成功闭环

- 测试点详情：验证订单首次取消成功后再次出现取消请求时，系统能够保持订单取消结果并控制库存释放副作用。

- 预期结果：库存不重复释放。

#### TP-006 验证取消请求幂等与副作用

##### TP-006-001 首次取消成功后的再次取消幂等处理

- 测试点详情：验证本人订单首次取消成功后再次提交取消请求时，系统不会重复释放库存。

- 预期结果：库存不重复释放。

##### TP-006-002 并发取消请求的幂等识别规则

- 测试点详情：验证同一订单在短时间内出现并发取消请求时，系统对并发请求的识别和归并是否有明确设计依据。

- 预期结果：不产生重复业务副作用；不补写未说明的错误码、提示文案或状态值。

- 测试点详情：验证客服审核完成后，订单状态变化和后续处理是否有明确规则支撑。

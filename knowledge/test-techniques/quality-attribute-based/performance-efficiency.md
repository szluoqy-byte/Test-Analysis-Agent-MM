# 基于质量属性的性能效率测试技术

## 方法定义

性能效率测试技术关注系统在指定负载、数据量或资源约束下完成业务处理的能力。它验证响应时间、吞吐量、容量、资源使用和批处理耗时是否满足目标或基线。

该技术不替代性能测试工具或压测脚本，而是指导从测试点生成性能效率测试设计项和叶子节点可观察预期结果依据。

## 适用场景

- 测试点提到性能、响应时间、吞吐量、容量、并发、批量处理。
- 大数据量列表、导出、统计、搜索、分页。
- 定时任务或批处理耗时。
- 接口在典型负载下的响应表现。
- 用户操作要求在可接受时间内完成。

## 不适用场景

- 只验证功能是否正确，应使用基于规格的测试。
- 重点是失败恢复、重试、降级，应使用可靠性与恢复性。
- 没有任何可观察指标时，应登记待确认问题，并使用保守阈值表达。

## 建模输入

| 元素 | 说明 |
|---|---|
| 业务场景 | 被验证的操作、接口或任务 |
| 性能指标 | 响应时间、吞吐量、耗时、资源占用 |
| 负载条件 | 用户数、请求数、数据量、批量大小 |
| 观察方式 | 页面耗时、接口耗时、任务日志、监控指标 |
| 通过阈值 | 明确阈值或项目约定 |
| 数据规模 | 基准、典型、大数据量、峰值 |

## 设计步骤

1. 明确业务动作和性能指标。
2. 明确测试负载：单用户、典型并发、峰值、批量数据。
3. 明确数据规模和环境前提。
4. 设计基准性能测试设计项。
5. 设计容量或大数据量测试设计项。
6. 对高风险场景补充峰值、连续执行或资源使用验证。
7. 如果没有明确阈值，写入待确认问题，并使用“符合项目性能基线”作为临时判定口径。

## 测试设计项派生规则

| 场景类型 | 派生方式 |
|---|---|
| 基准响应 | 单用户或低负载下完成业务操作 |
| 典型负载 | 常规并发或常规数据量 |
| 容量边界 | 接近业务上限的数据量或请求量 |
| 峰值负载 | 高峰并发或批量处理 |
| 资源效率 | CPU、内存、数据库连接、队列积压 |

## 数量控制

- 没有明确性能目标时，不扩展大量性能测试设计项。
- `Level 0/1` 性能测试点至少覆盖基准和关键容量边界。
- 普通性能关注点可只生成一条典型负载测试设计项。
- 性能测试设计项应避免与功能测试设计项重复，只强调负载和指标。

## 输入条件与数据依赖关注

- 准备指定规模的数据量。
- 明确测试环境、账号、配置和监控入口。
- 明确性能基线或阈值来源。
- 准备清理或隔离历史数据，避免影响结果。

## 测试设计项生成关注

- 触发业务操作并记录开始、结束或监控指标。
- 对并发或批量场景说明负载规模。
- 对任务耗时说明任务触发和完成观察方式。

## 预期结果依据

- 响应时间或任务耗时满足阈值。
- 吞吐量达到目标或基线。
- 大数据量下结果正确且页面或接口可用。
- 资源使用无异常飙升。
- 超时或接近阈值时有合理提示或保护。

## 常见误区

- 只写“性能正常”，没有指标。
- 不说明数据量、并发量或负载条件。
- 把性能测试设计项写成普通功能测试设计项。
- 没有观察方式，导致无法判定。

## 测试设计项示例

### 示例：交易查询接口性能

**测试场景**：运营人员查询交易列表、按回执号检索交易，并导出交易数据。

**规格摘要**：

- 交易库中存在 `1,000,000` 条历史交易数据。
- 交易列表在 `50` 并发用户下 P95 响应时间不超过 `2s`。
- 按回执号精确查询的 P95 响应时间不超过 `1s`。
- 单次导出 `100,000` 条交易记录应在 `5min` 内完成。
- 最大分页大小下列表查询不能超时。

**测试点**：验证交易查询与导出在典型负载和容量边界下满足性能指标。

| 测试设计项 ID | 条件/数据/状态/组合 |
|---|---|
| TDI-001 | historyTransactionCount=1,000,000；queryType=按回执号精确查询；receiptNo=RCPT_20260602_0001 |
| TDI-002 | concurrentUsers=50；operation=查询交易列表；pageSize=20 |
| TDI-003 | exportRecordCount=100,000；operation=单次导出交易记录 |
| TDI-004 | pageSize=系统允许最大分页大小；operation=查询交易列表 |

**设计要点**：

- 性能设计项必须写清负载、数据量、指标和观察对象。
- 若需求没有给出阈值，不生成大量性能项；预期结果写 `待人工分析确认` 或“符合项目性能基线”。
- 性能项仍要保留业务正确性观察，避免只看耗时。

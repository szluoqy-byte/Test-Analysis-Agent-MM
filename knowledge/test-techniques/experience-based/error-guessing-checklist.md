# 基于经验的错误推测与检查清单

## 方法定义

基于经验的测试通过历史缺陷、专家经验、上线事故、常见遗漏和系统特性推测潜在错误，并补充规格测试可能遗漏的标题项。它不是替代基于规格的测试，而是在已有设计方案上增加高价值风险场景。

错误推测强调“哪里最可能出错”，检查清单强调“哪些常见问题必须扫一遍”。

## 适用场景

- 测试点来自历史缺陷或线上事故。
- 模块存在长期高发问题。
- 需求描述较简单，但测试人员知道实现易错点。
- 涉及缓存、异步、权限、并发、幂等、数据一致性。
- 评审时发现规格技术覆盖了规则，但没有覆盖常见失败方式。

## 不适用场景

- 需求规则尚不清楚时，不能只靠经验猜测生成标题项。
- 已有明确范围、状态、判定、周期或接口结构时，应先使用对应规格技术。
- 经验项没有可观察结果时，不应强行生成标题项。

## 输入来源

| 来源 | 示例 |
|---|---|
| memory | 历史缺陷、评审偏好、常见遗漏 |
| 测试点风险备注 | “历史出现过重复扣款”“容易越权” |
| 业务域特点 | 资金、库存、缓存、异步任务 |
| 技术实现特点 | 队列、定时任务、分布式锁、回调 |
| 专家检查清单 | 空值、重复提交、并发、超时 |

## 设计步骤

1. 读取测试点和 context pack，识别是否存在历史风险。
2. 判断风险是否已被主规格技术覆盖。
3. 未覆盖时生成补充标题项；已覆盖时在原标题项中强化判定关注。
4. 将经验项转化为可落地触发条件。
5. 明确可观察结果，例如状态、记录、日志、通知、拦截。
6. 根据风险影响调整标题项等级。
7. 去除无法触发、无法观察或与现有标题项重复的经验项。

## 常见检查清单

| 类别 | 检查项 | 常见标题项方向 |
|---|---|---|
| 空值与缺省 | 必填为空、选填为空、默认值未配置 | 拦截、默认处理 |
| 重复提交 | 连续点击、重复请求、重复回调 | 幂等、防重复 |
| 并发 | 多用户同时操作同一对象 | 锁、库存、状态一致 |
| 权限 | 越权访问、角色切换、租户隔离 | 拦截、数据隔离 |
| 缓存 | 修改后缓存未刷新、旧数据展示 | 前后端一致 |
| 异步 | 任务延迟、回调失败、消息重复 | 重试、补偿、最终一致 |
| 边界 | 时间跨天、金额精度、数量为 0 | 边界处理 |
| 审计 | 关键操作无日志、日志字段缺失 | 可追踪 |

## 缺陷模式卡片

缺陷模式只能作为经验启发，不单独创造业务规则。没有需求依据时，应输出待确认问题或风险确认点。

| 模式ID | 触发信号 | 典型风险 | 推荐主技术 | 标题项方向 | 待确认问题 |
|---|---|---|---|---|---|
| DP-INPUT-001 | 空值、null、缺失、默认值、纯空白、超长、不支持格式 | 校验缺失、默认值不一致、错误提示不清 | 等价类与边界值、接口契约 | 缺失、非法输入、默认输入处理 | 缺失、非法或默认输入的处理规则是否明确 |
| DP-BOUNDARY-001 | 金额、数量、比例、时间窗口、分页、批量上限、配额 | 边界内外处理错误、临界值比较符错误 | 等价类与边界值 | 边界内、边界点、边界外处理 | 阈值是否包含等于边界，超限后如何处理 |
| DP-STATE-001 | 生命周期、审批、订单状态、支付状态、终态 | 非法迁移、终态再次修改、重复触发 | 状态转换 | 非法迁移、重复触发、终态保护 | 源状态、目标状态和终态约束是否完整 |
| DP-FLOW-001 | 取消、回滚、重试、超时、补偿、下游失败 | 部分成功、补偿遗漏、恢复路径不明确 | 场景流、状态转换、数据一致性 | 中断、超时、下游失败后的恢复和补偿 | 失败后是否回滚、补偿或保留中间状态 |
| DP-PERM-001 | 角色、租户、归属人、数据范围、审批权限 | 未授权、横向越权、纵向越权、跨租户泄露 | 权限矩阵、风险策略 | 非授权资源、跨数据范围访问拦截 | 角色、资源、动作和数据范围是否完整定义 |
| DP-PERM-002 | 角色变更、权限过期、授权缓存、默认权限 | 权限缓存未失效、默认权限过宽 | 权限矩阵、数据一致性 | 权限变更后的访问范围和可见数据 | 权限变更何时生效，缓存如何失效 |
| DP-API-001 | API、字段、响应、错误码、回调、外部系统 | 契约不一致、错误码不匹配、兼容被破坏 | 接口契约、组合兼容 | 字段缺失、错误响应、版本差异 | 必填字段、错误码、兼容策略是否明确 |
| DP-API-002 | 超时、重试、幂等、重复回调、乱序回调 | 重复扣减、重复状态迁移、回调覆盖新状态 | 接口契约、状态转换、数据一致性 | 超时、重试、重复回调下的幂等和一致性 | 幂等键、回调去重和乱序处理规则是什么 |
| DP-DATA-001 | 创建、更新、删除、软删除、缓存、搜索、导出、统计 | 缓存未刷新、软删除可见、汇总和明细不一致 | 数据一致性 | 数据变更后在缓存、搜索、导出和统计中的一致性 | 数据变更后哪些视图需要同步刷新 |
| DP-DATA-002 | 迁移、回填、异步同步、对账、最终一致性 | 历史数据遗漏、异步状态不一致、对账不可恢复 | 数据一致性、场景流 | 异步或迁移流程在部分成功和重试场景下最终一致 | 同步时机、重试策略和对账规则是否明确 |
| DP-COMPAT-001 | 多版本、多平台、开关、灰度、渠道、语言地区 | 新老版本不兼容、开关回滚异常、配置组合遗漏 | 数据组合、场景流 | 不同版本、开关和渠道组合下的功能表现 | 旧版本、关闭开关和降级场景的行为是否明确 |
| DP-CONC-001 | 并发提交、重复点击、批量处理、队列消费 | 重复创建、重复扣减、顺序错乱、锁竞争 | 风险策略、数据一致性、接口契约 | 并发或重复触发场景下的副作用去重 | 并发控制、幂等键或去重规则是否明确 |
| DP-CONFIG-001 | 配置变更、开关切换、灰度策略、规则发布 | 配置未生效、旧配置残留、回滚失败 | 数据组合、场景流、数据一致性 | 配置开启、关闭和变更后的规则生效及回滚 | 配置何时生效，是否支持灰度和回滚 |
| DP-BATCH-001 | 导入、导出、批量审批、批量更新 | 部分成功不可见、错误行丢失、批量回滚不一致 | 场景流、数据一致性 | 批量处理部分成功和失败后的结果、反馈和审计 | 部分成功如何展示，失败项如何重试或回滚 |
| DP-PRIV-001 | 手机号、证件号、地址、支付信息、敏感日志 | 敏感信息泄露、脱敏不一致、权限扩大 | 风险策略、权限矩阵 | 敏感信息展示、导出、日志和接口响应保护 | 哪些字段需要脱敏，哪些角色可以查看明文 |

## 标题项派生规则

| 经验信号 | 派生方式 |
|---|---|
| 历史缺陷 | 生成同类回归标题项，并明确“不复现”的可观察结果 |
| 常见遗漏 | 生成检查清单补充标题项 |
| 高发风险 | 提高等级或补充异常路径 |
| 技术风险 | 叠加幂等、重试、并发、缓存一致性验证 |

## 数量控制

- 每个测试点最多补充 1 到 3 个经验标题项。
- 与主技术完全重复的经验项不单独生成。
- 低风险经验项可写入覆盖审查备注，不生成标题项。
- 历史线上事故和资金类缺陷优先保留独立标题项。
- 同类缺陷模式产生的标题项应合并，避免因为模式命中数量多而重复输出泛化标题。

## 输入条件与数据依赖关注

- 构造历史缺陷复现条件或同类条件。
- 准备并发、重复、缓存、异步所需的数据状态。
- 明确如何观察是否复现。

## 标题项生成关注

- 操作要能触发易错点，例如重复点击、重复请求、切换角色、等待任务。
- 不要只写“检查历史问题是否修复”，必须写出触发动作。
- 并发和异步标题项要说明触发顺序或等待条件。

## 判定关注

- 历史缺陷不复现。
- 重复、并发或异步场景下数据一致。
- 越权或非法操作被拦截。
- 缓存、日志、通知、审计满足判定关注。

## 常见误区

- 把经验清单当成固定模板，所有模块都套一遍。
- 只写“验证历史缺陷已修复”，没有触发条件或观察对象。
- 经验标题项和规格标题项重复，造成冗余。
- 缺少可观察结果，导致无法判定。

## 标题项示例

| 经验信号 | 标题项建议 | 判定关注 |
|---|---|---|
| 重复提交 | 验证用户连续提交订单时系统只生成一笔订单 | 结果幂等，不重复生成 |
| 缓存风险 | 验证权限变更后用户立即访问旧入口被拦截 | 缓存刷新且权限生效 |
| 历史缺陷 | 验证回调重复到达时结算记录不重复生成 | 只保留一条有效记录 |

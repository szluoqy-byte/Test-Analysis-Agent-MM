# 因果图测试技术

## 方法定义

因果图测试技术用于分析输入原因和输出结果之间的逻辑关系。它先识别原因、结果和约束，再将逻辑关系转换为判定表或关键组合测试设计项。

因果图本身通常不是最终测试设计项，而是建模工具。最终测试设计项应落到判定表、数据组合或具体场景。

## 适用场景

- 多个输入原因通过与、或、非关系共同影响结果。
- 规则文本复杂，直接写判定表容易遗漏。
- 存在互斥、唯一、包含、要求等约束。
- 需要解释为什么某些条件组合会触发某个结果。

## 不适用场景

- 条件和动作关系已经清晰成表，应直接使用判定表。
- 只有单个判断点，应使用判定点。
- 重点是状态或周期，不应强行建立因果图。

## 建模输入

| 元素 | 说明 |
|---|---|
| 原因 | 输入条件、业务条件、环境条件 |
| 结果 | 系统动作、输出、状态变化、提示 |
| 逻辑关系 | 与、或、非、异或、蕴含 |
| 约束 | 互斥、唯一、包含、要求、屏蔽 |
| 派生表 | 从因果图转换出的判定表或组合表 |

## 设计步骤

1. 从测试点中抽取原因和结果。
2. 将复杂语句拆成原子原因。
3. 建立原因到结果的逻辑关系。
4. 标记约束：
   - 互斥：两个原因不能同时为真。
   - 唯一：多个原因中只能有一个为真。
   - 包含：一个原因为真时另一个原因必须为真。
   - 要求：某结果发生需要指定原因。
5. 将因果图转换为判定表或关键组合。
6. 删除不可能组合。
7. 为每个结果和关键约束派生测试设计项。

## 测试设计项派生规则

| 关系类型 | 派生方式 |
|---|---|
| 与关系 | 所有必要原因同时满足时触发结果 |
| 或关系 | 任一原因满足时触发结果 |
| 非关系 | 原因不满足时触发替代结果 |
| 互斥约束 | 验证互斥原因无法同时成立或按优先级处理 |
| 包含约束 | 验证缺少被包含条件时系统拦截 |

## 数量控制

- 因果图复杂时，最终测试设计项不要覆盖所有布尔组合。
- 优先覆盖每个结果至少一次。
- 优先覆盖约束违反场景。
- 高风险结果保留多个关键原因组合。

## 输入条件与数据依赖关注

- 准备能够分别满足关键原因的输入或业务状态。
- 对互斥或包含关系，明确如何构造违反约束的数据。
- 确认结果可观察。

## 测试设计项生成关注

- 按原因组合构造输入。
- 触发系统判断。
- 不在同一测试设计项中验证多个结果。

## 预期结果依据

- 触发的结果与逻辑关系一致。
- 约束冲突被正确处理。
- 优先级、拒绝原因和状态变化可判定。
- 不可能组合不会被错误接受。

## 常见误区

- 把因果图作为最终输出，不转换为可落地测试设计项。
- 原因不是原子条件，导致组合含糊。
- 忽略互斥和包含约束。
- 穷举所有组合，产生大量低价值测试设计项。

## 测试设计项示例

### 示例：实名与风控原因共同决定转账放行

**测试场景**：用户提交钱包转账请求，系统根据实名、收款账户、金额限额和风控名单决定是否放行。

**规格摘要**：

- 原因 A：付款用户已实名。
- 原因 B：收款账户状态正常。
- 原因 C：转账金额未超过单笔限额。
- 原因 D：付款用户命中高风险名单。
- 结果 R1：仅当 A、B、C 为真且 D 为假时允许转账。
- 结果 R2：A 为假时拒绝并返回 `KYC_NOT_VERIFIED`。
- 结果 R3：B 为假时拒绝并返回 `PAYEE_INVALID`。
- 结果 R4：C 为假时拒绝并返回 `AMOUNT_LIMIT_EXCEEDED`。
- 结果 R5：D 为真时拒绝并返回 `RISK_BLOCKED`，且优先级高于其他拒绝原因。

**测试点**：验证转账放行原因、拒绝结果和高风险屏蔽优先级。

| 测试设计项 ID | 条件/数据/状态/组合 | 预期结果 |
|---|---|---|
| TDI-001 | 已实名、收款账户正常、金额未超限且未命中高风险名单 | 转账请求允许提交 |
| TDI-002 | 未实名、收款账户正常、金额未超限且未命中高风险名单 | 转账被拒绝，返回 `KYC_NOT_VERIFIED` |
| TDI-003 | 已实名、收款账户异常、金额未超限且未命中高风险名单 | 转账被拒绝，返回 `PAYEE_INVALID` |
| TDI-004 | 已实名、收款账户正常、金额超过单笔限额且未命中高风险名单 | 转账被拒绝，返回 `AMOUNT_LIMIT_EXCEEDED` |
| TDI-005 | 已实名、收款账户正常、金额未超限但命中高风险名单 | 转账被拒绝，返回 `RISK_BLOCKED` |
| TDI-006 | 未实名且命中高风险名单 | 转账被拒绝，返回 `RISK_BLOCKED`，验证高风险屏蔽优先级 |

**设计要点**：

- 因果图示例要把原因、结果和优先级说清楚，再落成设计项。
- 每条设计项只验证一个预期结果，避免同时断言多个拒绝原因。
- 若需求未说明错误码或拒绝优先级，预期结果写 `待人工分析确认`。

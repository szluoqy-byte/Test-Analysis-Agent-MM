# 测试工作流边界

本文档定义本仓库测试分析、测试设计、测试技术和执行级用例之间的公共边界。它只维护跨 skill 共用的稳定术语和层级关系；具体输出结构、字段、生成细则维护在对应的 `knowledge/*-solution-standard.md` 和 `skills/*/references/` 中。覆盖检查保留在 `skills/coverage-review/references/coverage-check.md`；确定性 JSON/Markdown 校验由 `bin/` 脚本负责。

## 稳定术语

| 术语 | 含义 | 备注 |
|---|---|---|
| 需求文档 | 输入给 Agent 的 Markdown 产品、系统或业务需求说明 | 可以与设计方案一起输入 |
| 设计方案 | 可选输入，用于补充接口、字段、状态、权限、数据依赖、配置和非功能约束 | 不得编造缺失设计事实 |
| 需求依据 | 测试场景、测试点或测试点明细对应的需求标题、段落、表格行、规则或风险确认点 | 用于可追踪性 |
| 方法证据 | 专项测试技术分析后的 `ME-*` 证据摘要 | 用于证明测试技术被实际应用 |
| 记忆上下文包 | 每次分析前从长期 memory 和 project/personal 补充中筛选出的上下文摘要 | 写入 `outputs/runs/<run-id>/process/context-pack.json`，同名 Markdown 为派生阅读版 |
| 测试场景 | 从需求和设计方案中识别出的业务使用、系统触发或专项质量验证情境 | 使用 `SC-*` |
| 测试点 | 场景下需要验证的规则、路径、风险、接口契约、状态或质量关注点 | 使用 `TP-*` |
| 测试点明细 | 测试点下的规则分支、路径分支、状态分支、权限分支、接口契约分支或风险分支 | 使用 `TP-*-*` |
| 失败类型明细 | 非成功测试点明细下的失败来源、失败类型或异常路径拆分 | 使用 `TP-*-*-*`，仅非成功测试点明细需要 |
| 预期结果 | 需求或设计方案明确支持的简短判定结果；依据不足时写 `待人工分析确认` | 不展开完整用例预期清单 |
| 测试设计项 | 测试设计层基于普通测试点明细或失败类型明细选择的代表性条件、数据、状态或组合 | 使用 `TDI-*`，由 `test-design-agent` 输出 |
| 测试技术 | 用于支持测试分析和测试设计的方法或启发，例如等价类、边界值、判定表、状态转换、错误推测和风险驱动 | 维护在 `knowledge/test-techniques/` |

## 核心边界

| 阶段 | 回答的问题 | 主要产物 | 不做什么 |
|---|---|---|---|
| Test Analysis 测试分析 | what to test：测什么、为什么测、覆盖哪些规则分支和风险 | 测试场景、测试点、测试点明细、非成功失败类型明细、方法证据、过程缺口候选 | 不写完整测试步骤、具体执行数据和测试设计项表 |
| Test Design 测试设计 | how to test this point：每个普通测试点明细或失败类型明细用哪些代表性条件、具体数据值、数据槽位、状态、接口返回或组合覆盖 | 测试设计项、叶子节点预期结果 | 不写完整测试步骤、自动化脚本和执行数据清单 |
| Test Technique 测试技术 | 用什么方法分析和设计 | 等价类、边界值、判定表、状态转换、风险驱动等方法证据 | 技术产物不直接泄漏到主交付件 |
| 执行级用例细化 | 怎么执行、用哪些数据、步骤和完整预期来测 | 不由本 Agent 输出 | 不在本仓库维护执行级用例写作知识 |

## 层级关系

测试分析主交付件固定停留在分析层：

```text
需求 + 可选设计方案
  -> 测试场景
      -> 测试点
          -> 测试点明细
              -> 失败类型明细（仅非成功测试点明细）
```

测试设计主交付件在已评审测试分析方案基础上补充设计层：

```text
测试场景
  -> 测试点
      -> 测试点明细
          -> 失败类型明细（如分析方案已有）
              -> 测试设计项
          -> 测试设计项（普通测试点明细）
```

`test-analysis-agent` 不输出 `TDI-*` 测试设计项；`test-design-agent` 输出 `TDI-*` 测试设计项，但不输出完整测试用例、前置步骤、测试步骤、自动化脚本或执行数据清单。

## 测试技术使用边界

测试技术可同时支持测试分析和测试设计，但两个阶段的产物不同：

| 测试技术使用位置 | 输入 | 输出 | 边界 |
|---|---|---|---|
| 测试分析层 | 输入事实模型、context pack、测试技术路由 | 分析维度、测试技术路由、`ME-*` 方法证据、测试点候选、过程缺口候选 | 回答 what to test，不把边界值清单、判定表或状态矩阵直接写入主交付件 |
| 测试分析方案生成层 | 输入事实模型、方法证据、测试点候选、风险分析结果 | 场景、`TP-*` 测试点、`TP-*-*` 测试点明细、预期结果 | 将技术产物上收为可理解的业务验证目标，并识别分析分支；不生成 TDI、执行步骤、自动化脚本或数据清单 |
| 测试设计层 | 评审后的测试分析方案、输入事实模型、测试技术 | `TDI-*` 测试设计项 | 由 `test-design-agent` 承接普通 `TP-*-*` 或失败类型 `TP-*-*-*`，不由测试分析方案输出 |

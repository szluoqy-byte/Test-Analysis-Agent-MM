# 风险级别判定规则

本文件定义测试点从风险原因到 `Level 0` 到 `Level 4` 的判定启发。级别定义仍以 `knowledge/testpoint-standard.md` 为准，本文件只说明如何判断。

## 判定维度

| 维度 | 高风险信号 |
|---|---|
| 业务影响 | 核心链路、支付、结算、下单、审批、发布、登录、权限变更 |
| 失败代价 | 资损、数据丢失、越权、安全隐患、不可逆状态、外部客户影响 |
| 可恢复性 | 无法自动恢复、恢复成本高、需要人工介入、影响历史数据 |
| 发生概率 | 历史缺陷频发、常用路径、高并发、批量操作、外部依赖不稳定 |
| 观测能力 | 缺少日志、告警、对账、审计或人工恢复路径 |
| 回归价值 | 每个版本都需要验证、迭代必测、发布前完整验证、仅首次验证 |

## 风险评分启发

先按以下维度粗略计分，再映射级别。计分用于辅助判断，不替代需求依据。

| 分数 | 判定 |
|---|---|
| 0 | 无明显风险或仅展示影响 |
| 1 | 单一低损失影响，可快速恢复 |
| 2 | 影响常用路径、重要数据或关键角色 |
| 3 | 影响核心链路、资损、越权、不可逆或外部客户 |

| 总分 | 建议级别 |
|---|---|
| 8 分及以上，或任一维度为 3 且涉及核心链路 | `Level 0` |
| 5 到 7 分，或任一维度为 3 | `Level 1` |
| 3 到 4 分 | `Level 2` |
| 1 到 2 分 | `Level 3` |
| 0 分且低频或生僻 | `Level 4` |

## 级别映射

| 级别 | 判定规则 | 典型场景 |
|---|---|---|
| `Level 0` | 核心链路或高损失场景，失败后版本核心能力受损或没有继续验证价值 | 支付成功、订单提交、权限核心隔离、库存扣减、不可逆状态提交 |
| `Level 1` | 特性关键功能或关键可靠性，失败会阻塞当前特性验证 | 核心异常恢复、关键接口契约、重要状态迁移、关键兼容路径 |
| `Level 2` | 系统重要功能，适合 TR 点或对外发布版本完整验证 | 主要业务规则、常见边界、重要数据同步、常用角色路径 |
| `Level 3` | 一般功能，适合大版本或变更范围相关回归 | 低风险分支、补充路径、普通展示或非核心兼容 |
| `Level 4` | 生僻场景或特殊预置条件，首次验证后通常不进入常规回归 | 低频配置、罕见组合、历史兼容边缘场景 |

## 调整规则

- 需求涉及资金、权限、数据删除、不可逆状态、跨系统回调时，至少评估为 `Level 1`，除非需求明确说明影响极低。
- 同时涉及核心链路和不可逆/资损/越权风险时，优先评估为 `Level 0`。
- 只有用户体验、展示、低频配置且失败可快速恢复时，才考虑 `Level 3` 或 `Level 4`。
- 如果风险来自假设而非明确需求，应标记为风险确认点，不直接提高到 `Level 0`。
- 级别与风险备注必须一致；高等级测试点需要说明高风险原因。

## 上调规则

- 覆盖支付、结算、库存、权限核心隔离、审批发布等核心链路时，至少上调到 `Level 1`。
- 涉及跨系统回调、异步最终一致、批量不可逆操作时，至少上调到 `Level 1`。
- 同时影响多个用户、多个租户或外部客户时，至少上调到 `Level 1`。
- 历史缺陷或 memory 中确认过反复出现的问题，可上调一级。
- 缺少日志、告警、对账或恢复信号且失败难以恢复时，可上调一级。

## 下调规则

- 仅影响文案、展示排序、低频配置且可快速恢复时，可下调到 `Level 3` 或 `Level 4`。
- 需求明确说明为实验性、灰度小流量且有关闭开关时，可下调一级，但仍需覆盖关闭和回滚。
- 风险只来自通用缺陷模式而当前需求没有支撑时，不直接上调；写为风险确认点或待确认问题。

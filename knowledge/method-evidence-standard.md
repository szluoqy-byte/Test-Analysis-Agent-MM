# 测试方法证据标准

本文件定义每种测试方法在生成测试点之前应留下的分析证据。方法证据用于证明测试理论被真正应用，而不是只在测试点表中填写方法名称。分析维度以 `knowledge/test-analysis-methodology.md` 为准，方法证据应能说明该维度下识别出了哪些测试条件、覆盖项或缺口。

## 通用证据字段

| 字段 | 说明 |
|---|---|
| 证据ID | `ME-001`、`ME-002`，按最终报告顺序递增 |
| 方法 | 使用的测试方法，例如状态迁移、决策表、权限矩阵 |
| 需求片段 | 被分析的需求摘要 |
| 分析结论 | 该方法识别出的关键对象、规则、风险或覆盖点；必要时注明分析维度 |
| 关联测试点/待确认 | 关联的测试点 ID 或待确认问题 ID |

## 证据质量要求

- 证据必须先于测试点生成，用来解释测试点为什么存在。
- `需求片段` 必须能回到需求标题、段落、表格行、接口字段或状态描述。
- `分析结论` 不能只写“需要覆盖”；必须说明关键对象、条件、风险或覆盖策略。
- `分析结论` 应能落到主交付件中的场景、场景条件、测试点、接口详情或待确认信息之一。
- `关联测试点/待确认` 不能为空。无法生成测试点时，必须关联待确认问题。
- 同一证据可以关联多个测试点，但不能跨多个无关需求片段。
- 同一测试点可以被多个证据支撑，但测试点表中只保留主方法，其他关联留在方法证据摘要中。

## 方法证据要求

| 方法 | 必备证据 | 典型证据表达 |
|---|---|---|
| 风险驱动 | 风险点、失败模式、影响、建议级别、需求依据 | 支付回调重复可能导致重复扣减，建议 Level 0 |
| 需求可测性 | 可验证对象、可测性等级、缺失信息、待确认问题 | 订单状态规则可测，但审核后状态缺失 |
| 边界值 | 输入域/业务域、边界点、边界内外、有效/无效类 | 金额门槛覆盖低于、等于、高于门槛 |
| 等价类 | 有效类、无效类、默认类、特殊类 | 商品分类覆盖适用类和不适用类 |
| 状态迁移 | 状态对象、源状态、事件、目标状态、非法迁移、终态 | 已支付订单不能再次使用优惠券 |
| 决策表 | 条件、条件取值、动作/结果、冲突/默认分支 | 会员等级、券状态、商品范围共同决定优惠适用 |
| 场景流 | 参与方、主流程、备选流程、异常流程、中断恢复 | 支付失败后保留待支付并允许重新支付 |
| 权限矩阵 | 角色、资源、动作、数据范围、允许/拒绝关系 | 普通用户只能操作自己的资源 |
| 接口契约 | 提供方/消费方、请求字段、响应字段、错误码、超时/重试/幂等 | 试算接口返回优惠金额和不可用原因 |
| 数据一致性 | 数据对象、变更点、派生数据、缓存/统计/日志、副作用 | 支付成功后订单、优惠券、库存和日志一致 |
| 组合兼容 | 因子、取值、关键组合、不兼容组合、默认组合 | App 5.0 与老版本展示规则不同 |
| 错误推测 | 历史缺陷模式、失败触发、影响范围、建议覆盖 | 重复提交可能造成重复释放库存 |

## 方法最低证据颗粒度

| 方法 | 最低颗粒度 | 缺失时的待确认方向 |
|---|---|---|
| 边界值 | 至少说明一个输入域或业务域、边界点和边界归属 | 边界是否包含等于、超限后如何处理 |
| 等价类 | 至少说明有效类、无效类或默认类之一 | 哪些类别有效、无效或走默认处理 |
| 状态迁移 | 至少说明状态对象、源状态、事件和目标状态 | 源/目标状态、终态、非法迁移是否明确 |
| 决策表 | 至少说明两个以上条件及其结果 | 条件优先级、默认分支、冲突处理 |
| 场景流 | 至少说明参与方、主路径和一个异常/备选路径 | 中断、失败、补偿或恢复规则 |
| 权限矩阵 | 至少说明角色、资源、动作和允许/拒绝关系 | 数据范围、归属、租户或审批权限 |
| 接口契约 | 至少说明请求字段、响应字段或错误契约 | 必填、可空、错误码、超时、幂等、回调 |
| 数据一致性 | 至少说明主数据对象和一个派生/副作用对象 | 缓存、统计、日志、补偿或对账规则 |
| 组合兼容 | 至少说明两个因子及其关键组合 | 支持矩阵、降级策略、旧版本行为 |
| 风险驱动 | 至少说明失败模式、影响和建议级别 | 风险是否成立、影响范围和恢复成本 |

## 使用规则

- 每个标记为 `必选` 的方法，最终报告中必须有方法证据，或有待确认问题解释为什么无法形成证据。
- 测试点明细不新增证据列；证据关联写在“方法分析证据摘要”中，测试点仍保持轻量。
- 方法证据不能代替需求依据。证据必须能追溯到需求片段或风险确认点。
- 方法证据不得直接引入需求没有说明的业务规则；只能登记风险或待确认问题。

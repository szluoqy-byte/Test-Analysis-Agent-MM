# 测试判定依据启发

本文件用于判断测试点是否“可验证”。

## 判定依据来源

- 需求文本：明确规则、状态、阈值、接口或验收说明。
- 业务不变量：必须始终成立的业务条件，例如不能重复释放库存。
- 数据不变量：计数、状态、归属、可见性或审计一致性。
- 契约不变量：请求字段、响应字段、错误码、回调或兼容规则。
- 权限不变量：参与方、资源、动作、数据范围、租户和归属关系。
- 历史缺陷：memory 中确认过的失败模式。

## Oracle 类型

| 类型 | 适用场景 | 示例表达 |
|---|---|---|
| 规则 Oracle | 业务规则、校验、限制、优先级 | 订单金额达到门槛时优惠券可用 |
| 状态 Oracle | 生命周期、审批流、终态和非法迁移 | 已关闭订单不能重新支付 |
| 数据 Oracle | 主数据、派生数据、缓存、统计和日志 | 支付成功后订单、库存和日志一致 |
| 契约 Oracle | 接口字段、错误码、回调和幂等 | 缺少必填字段时返回约定错误码 |
| 权限 Oracle | 角色、资源、动作、数据范围 | 普通用户不能访问他人订单 |
| 风险 Oracle | 历史缺陷、不变量和高损失失败模式 | 重复提交不会造成重复扣减 |

## 不变量检查点

| 不变量类型 | 检查点 |
|---|---|
| 业务不变量 | 业务对象是否满足规则、状态是否符合约束、金额/数量是否保持业务含义 |
| 数据不变量 | 主数据和派生数据是否一致、缓存/搜索/统计/导出是否同步、审计日志是否可追踪 |
| 权限不变量 | 角色是否只能访问授权资源、数据范围是否隔离、权限变更是否及时生效 |
| 契约不变量 | 请求字段、响应字段、错误码、兼容策略、幂等键和回调语义是否稳定 |
| 状态不变量 | 终态是否不可变、非法迁移是否被拒绝、重复事件是否不产生重复副作用 |

## 缺少判定依据时

- 不创建假的预期结果。
- 生成“待确认问题”。
- 如有价值，可生成风险确认点，并明确标记需求未完全说明。

## Oracle 强度

| 强度 | 说明 | 处理 |
|---|---|---|
| 强 | 需求明确给出规则、阈值、状态、字段或错误码 | 可直接生成测试点 |
| 中 | 需求给出目标，但缺少部分边界、异常或错误处理 | 生成测试点并保留待确认风险 |
| 弱 | 只有“合理、稳定、快速、正常”等泛化表达 | 先生成待确认问题 |
| 推测 | 只来自通用缺陷模式或经验启发 | 标记风险确认点，不写成已确认规则 |

## 不应作为 Oracle 的内容

- 纯实现猜测，例如“数据库应增加一条记录”但需求未说明数据影响。
- 具体测试数据，例如“输入 abc”，除非需求明确给出该数据。
- UI 操作步骤，例如“点击按钮后看到提示”，应改写为可观察业务结果。
- 通用最佳实践本身，例如“应该有日志”，除非需求、风险或项目 memory 支撑。

## 表达示例

- 好：`验证取消成功后库存释放与订单状态变更保持一致`。
- 差：`点击取消按钮后库存加 1 并显示取消成功`。

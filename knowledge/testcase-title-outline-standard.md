# 测试用例标题大纲标准

本文档定义本 Agent 的核心输出粒度：`测试用例标题大纲`。它承接测试分析的场景和测试点，也吸收标题级测试设计的模式选择能力，但不进入完整测试用例写作。

## 分层关系

```text
需求 + 设计方案
  -> 测试场景
      -> 场景测试条件
      -> 测试点
          -> 测试用例标题项
              -> 完整测试用例（不由本 Agent 输出）
```

## 核心定义

| 对象 | 定义 | 本 Agent 是否输出 |
|---|---|---|
| 测试场景 | 从需求和设计方案中识别出的业务使用、系统触发或专项质量验证情境 | 是 |
| 场景测试条件 | 场景级共用入口、角色、前置条件、测试数据因子、业务约束和设计方案约束 | 是 |
| 测试点 | 场景下需要验证的规则、路径、风险、接口契约、状态或质量关注点 | 是 |
| 测试用例标题项 | 由测试点结合设计模式派生出的标题级验证项，包含标题、覆盖意图、级别、输入条件与数据依赖、判定关注和待确认信息 | 是 |
| 完整测试用例 | 可执行产物，包含前置步骤、测试步骤和完整预期结果 | 否 |

## 标题项字段

| 字段 | 要求 |
|---|---|
| 标题项 ID | 使用 `TCT-001` 起全局连续编号 |
| 测试用例标题 | 表达被测对象、场景/条件和验证目标 |
| 覆盖意图 | 表达该标题项覆盖的路径、边界、状态、接口契约、权限、数据一致性、风险或质量属性 |
| 级别 | 使用 `Level 0` 到 `Level 4` |
| 输入条件与数据依赖 | 记录标题项可判定所需的角色、状态、字段、枚举、边界、配置、依赖服务和数据准备约束 |
| 判定关注 | 记录观察方向或 oracle，例如响应、状态、记录、错误码、日志、页面、通知、权限拦截或性能指标 |
| 待确认信息 | 记录影响该标题项被理解、评审或后续细化的信息缺口；无缺口写 `无` |

## 标题命名规则

推荐结构：

```text
验证<被测对象>在<条件/场景>下<验证目标>
```

示例：

- 验证下发订单 ID 总长度为 13 位时订单下发成功
- 验证下发订单 ID 总长度为 10 位时订单下发被拦截
- 验证普通用户在库存充足且地址有效时成功提交实物商品订单
- 验证订单已支付状态下重复支付请求不会生成重复支付记录
- 验证创建订单接口在缺少必填字段时返回字段校验错误

标题必须能独立回答三个问题：

1. 被测对象是什么。
2. 在什么条件、状态、输入或场景下验证。
3. 验证目标是什么。

## 输入条件与数据依赖

该字段用于承接用户提到的“输入条件/数据依赖”。推荐统一命名为 `输入条件与数据依赖`，因为它不仅包含输入值，还包含角色、状态、配置、依赖服务和数据准备关系。

适合写入：

- 角色和权限：普通用户、管理员、无权限用户、系统任务。
- 业务对象状态：订单待支付、订单已支付、商品上架、库存不足。
- 字段约束：长度、格式、必填、枚举、范围、精度、唯一性。
- 边界和等价类摘要：小于最小值、等于最大值、超过最大值、非法格式。
- 组合条件摘要：渠道、版本、角色、配置开关、状态组合。
- 接口依赖：请求字段、鉴权、幂等键、回调、消息主题、第三方服务。
- 数据依赖：订单与支付记录、主表与明细表、缓存与数据库、前后置数据状态。
- 非功能依赖：数据量、并发量、超时阈值、降级开关、故障注入条件。

不适合写入：

- 具体操作步骤。
- 完整测试数据表。
- 完整预期结果。
- 自动化脚本或接口调用代码。
- “按需求”“同上”“见设计方案”等非自包含占位。

## 判定关注

判定关注只描述观察方向，不展开完整预期结果。

合适示例：

- 订单下发接口响应状态和错误码。
- 订单状态、下发记录和消息发送记录。
- 页面提示、按钮状态和表格记录。
- 数据库记录、缓存状态和审计日志。
- 幂等响应、重复请求处理和唯一键约束。

不合适示例：

- “步骤 1 点击提交，步骤 2 查看结果。”
- “预期返回 200 且页面展示成功、数据库新增记录、日志包含 traceId。”（这已接近完整预期清单）
- “检查结果正确。”

## 粒度规则

- 一条标题项应对应一个清晰的验证目标。
- 高风险测试点可以拆成多条标题项，例如主路径、关键异常、边界、权限和幂等。
- 同一测试点下仅输入取值不同但风险和判定方向相同的内容，可以合并为一条标题项，并在 `输入条件与数据依赖` 中列出范围。
- 不同状态迁移、错误类型、接口契约、权限边界或缺陷定位方向，应拆成不同标题项。
- 不为了覆盖每个按钮、字段或具体数值机械生成标题项。

## 禁止项

- 不输出前置步骤、测试步骤、完整预期结果。
- 不使用 `操作步骤`、`测试数据`、`预期结果` 作为列名。
- 不把测试设计方法名称直接塞进标题，例如“边界值测试订单 ID”。
- 不把“正常/异常/校验通过/功能正确”作为标题主体。
- 不编造需求或设计方案没有给出的阈值、状态、错误码、接口路径或业务规则。

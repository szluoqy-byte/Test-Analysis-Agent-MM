# 状态迁移分析 Skill

本 skill 用于有状态对象和流程生命周期的测试分析。

## 职责边界

- 本 skill 只产出内部方法证据和状态相关测试点候选，供 `testpoint-generation` 归并为场景化测试点。
- 状态机、迁移矩阵、源状态和目标状态组合是过程产物，可沉淀为场景条件、数据因子、业务设计约束或测试点验证目标，但不直接作为最终用例设计。
- 标题大纲生成阶段会基于状态相关测试点生成测试用例标题项；本 skill 不建议完整用例数量、步骤或完整预期结果。

## 输入

- 结构化需求模型。
- 状态相关需求片段。
- 记忆上下文包。

## 分析步骤

1. 识别初始状态、中间状态、终态和异常状态。
2. 识别触发状态迁移的事件。
3. 区分合法迁移和非法迁移。
4. 检查重复触发、并发触发、回滚、取消、超时、重试和补偿路径。
5. 生成带需求依据的状态迁移测试点。
6. 对缺失初始状态、终态、回退规则、重复事件和异常补偿登记待确认候选。

## 输出

先输出方法分析证据：

| 证据ID | 方法 | 状态对象/事件 | 分析结论 | 关联测试点/待确认 |
|---|---|---|---|---|

再输出测试点候选：

| 状态对象 | 源状态 | 事件 | 目标状态 | 测试点 | 需求依据 | 级别 | 风险/备注 |
|---|---|---|---|---|---|---|---|

如存在状态机缺口，追加：

| 问题ID | checkpoint | sourceStage | header | question | why | impact | options | blockingLevel | priority | askPolicy | mustAsk | relatedRequirement | memoryConflict |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

## 约束

- 如果需求没有说明源状态或目标状态，生成“待确认问题”。
- 不凭空补完整状态机。
- 不把技术实现中的隐含状态当作业务状态，除非需求或 memory 明确说明。
- 最终主交付件中不输出状态迁移矩阵；只表达待验证的业务状态规则、合法/非法迁移或异常恢复目标。
- 不直接向用户提问。
- 如果 context pack 中的状态模型或项目因子不足，只能按 context pack 记录的来源或当前需求明确指向的文件补读相关章节，并在方法证据中记录来源；不得全目录搜索或全量复制大文件。

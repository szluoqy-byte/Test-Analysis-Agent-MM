# 测试技术方法参考记录指南

本文件定义 `testing-method-router` 和专项方法参考如何记录分析过程。方法参考记录只用于帮助生成阶段形成覆盖视角、风险判断和候选测试点，不是主交付件字段，也不是测试点成立的业务依据。

测试技术可以被组合、裁剪或跳过。最终 `test-analysis-solution.json` 只输出 `SC-*` 和 `TP-*`，并通过 `basisRefs[]` 追溯需求、设计、规则、动态来源或明确风险依据；不得输出 `methodRefs[]`。

## 建议记录字段

| 字段 | 说明 |
|---|---|
| 方法 | 使用或参考的测试技术，例如状态迁移、决策表、权限矩阵 |
| 需求片段 | 被分析的需求摘要 |
| 分析结论 | 该方法启发出的关键对象、规则、风险或覆盖点 |
| 候选落点 | 可选的候选 SC/TP 方向；不能确定时写 `not_applicable` 或 `insufficient_evidence` |
| 说明 | 方法适用、弱适用或不适用的原因 |

## 记录质量要求

- 方法参考记录不能代替需求依据；最终 TP 必须由 `basisRefs[]` 支撑。
- 记录应说明关键对象、条件、风险或覆盖策略，避免只写“需要覆盖”。
- 同一需求片段可以参考多个测试技术，最终由生成阶段合并为业务可读的 TP。
- 不要求每个被路由的测试技术都形成独立证据；如果输入事实已经能直接支撑测试点，优先输出清晰的业务测试点。
- 方法参考不得直接引入需求没有说明的业务规则，只能记录风险关注、覆盖视角或输入不足原因。

## 典型参考视角

| 方法 | 参考重点 |
|---|---|
| 风险驱动 | 风险点、失败模式、影响、建议级别、需求依据 |
| 需求可测性 | 可验证对象、可测性等级、缺失信息、保守处理说明 |
| 边界值 | 输入域/业务域、边界点、边界内外、有效/无效类 |
| 等价类 | 有效类、无效类、默认类、特殊类 |
| 状态迁移 | 状态对象、源状态、事件、目标状态、非法迁移、终态 |
| 决策表 | 条件、条件取值、动作/结果、冲突/默认分支 |
| 场景流 | 参与方、主流程、备选流程、异常流程、中断恢复 |
| 权限矩阵 | 角色、资源、动作、数据范围、允许/拒绝关系 |
| 接口契约 | 提供方/消费方、请求字段、响应字段、错误码、超时/重试/幂等 |
| 数据一致性 | 数据对象、变更点、派生数据、缓存/统计/日志、副作用 |
| 组合兼容 | 因子、取值、关键组合、不兼容组合、默认组合 |
| 错误推测 | 历史缺陷模式、失败触发、影响范围、建议覆盖 |

## 使用规则

- `必选` 表示该覆盖视角需要被重点考虑，不表示必须生成独立方法参考记录。
- 测试点不新增方法列，也不输出 `methodRefs[]`。
- review 和 coverage 只检查最终 SC/TP/TC 是否覆盖输入事实和风险，不按方法清单逐项打勾。
